Microsserviços

7 serviços independentes, cada um com repositório, banco de dados (MongoDB ou SQL Server) e pipeline CI/CD próprios.

OS Service

Ciclo de vida completo das Ordens de Serviço. Ponto de entrada da Saga — publica e consome eventos coreografados via RabbitMQ.

Billing Service

Orçamentos e pagamentos com integração ao Mercado Pago via webhook. Participa da Saga aguardando confirmação de pagamento.

Cadastro Service

Clientes, produtos e emissão de JWT. Único provedor de identidade do sistema — todos os serviços validam o token gerado aqui.

Estoque Service

Reserva e liberação de peças. Guardião de recursos na Saga — rollback automático ao consumir o evento os.cancelada.

Execução Service

Fila de execução dos reparos. Inicia após confirmação de pagamento e notifica o OS Service ao concluir.

BFF

Único ponto de entrada para o cliente. Valida JWT, roteia chamadas para os serviços downstream e serve o frontend React embutido.

Auth Service

Serverless em AWS Lambda. Autenticação por CPF e emissão de JWT. Único serviço com banco SQL Server no RDS (ACID para dados de identidade).

Clean Architecture

Arquitetura por Domínio

Cada microsserviço segue Clean Architecture com 4 camadas (Domain, Application, Infra, API), garantindo que as regras de negócio sejam agnósticas a banco de dados e frameworks.

  • Desacoplamento totalCada serviço tem seu próprio repositório, banco de dados e deploy independente.
  • MongoDB como banco principalSchema flexível para documentos heterogêneos em todos os 6 serviços de domínio.
  • SQL Server no Auth (Lambda)Banco relacional com garantias ACID para dados de identidade e autenticação.
  • CI/CD independenteGitHub Actions por repositório: testes, SonarCloud e deploy no ECS Fargate a cada push.

Saga Coreografado

Saga Pattern via RabbitMQ

Cada serviço conhece apenas os eventos que deve publicar e consumir. Sem orquestrador central — sem ponto único de falha.

Fluxo Principal

→ os.aberta
→ diagnostico.concluido
→ orcamento.aprovado
→ pagamento.confirmado
→ execucao.finalizada

Compensação

← orcamento.rejeitado
← pagamento.falhou
← os.cancelada
⚠ os.saga.dlq Dead Letter Queue

Desacoplamento Total

Nenhum serviço conhece os outros diretamente. Comunicação exclusiva via eventos.

Sem Ponto Único de Falha

Sem orquestrador central. Um serviço fora do ar não paralisa o restante.

Escalabilidade Independente

Cada serviço escala, faz deploy e opera sem coordenação explícita com os demais.

RabbitMQ Topic Exchange

Exchange tech.saga (Topic, durable) com Dead Letter Queue para falhas.

Fase 4

Infraestrutura & DevOps

7 serviços com deploy e CI/CD independentes. Containers no ECS Fargate, mensageria e banco centralizados no EC2.

AWS ECS Fargate

Containers serverless sem gerenciamento de EC2. Deploy independente por serviço com ALB dedicado. us-east-1

MongoDB 7

Schema flexível para documentos heterogêneos de OS, orçamentos e estoque. Rodando em EC2 t3.micro.

RabbitMQ 3.13

Suporte nativo a Topic Exchange e Dead Letter Queues. Exchange tech.saga (durable). Rodando no mesmo EC2.

AWS Lambda + RDS

Auth Service serverless por ser stateless e de baixa frequência. SQL Server no RDS pela necessidade de ACID em dados de identidade.

CI/CD — GitHub Actions

Pipeline independente por repositório: testes unitários + BDD, SonarCloud, build Docker, push ECR e deploy ECS a cada push em main.

SonarCloud

Análise estática e cobertura de testes integrada ao CI. Quality Gate: OK em todos os serviços. Cobertura acima de 90% nos serviços de domínio.
